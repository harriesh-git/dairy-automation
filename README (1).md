# Dairy Automation — Daily Sales Reporting

An n8n workflow that automatically generates and delivers daily sales summaries for a multi-region dairy distribution business — one detailed report per region, plus a company-wide ranked overview — all via Telegram, on a fixed schedule, with zero manual reporting.

## Problem

Daily sales reporting across multiple regions is repetitive and error-prone to do by hand — pulling numbers, formatting them consistently, and distributing them to the right regional teams and management every single day. This automates the entire reporting cycle end to end.

## What it does

1. **Trigger** — Runs automatically every day at 8 PM
2. **Seed (test only)** — Idempotently generates ~150 realistic synthetic orders for the day if none exist yet, so the pipeline can be demoed/tested safely without needing live production data
3. **Aggregate** — A single Postgres query groups confirmed orders by region, using `json_agg`/`json_build_object` to nest per-product totals directly in SQL
4. **Fan out** — The aggregated data feeds two parallel formatters:
   - **Per-region summary** — builds a hand-aligned monospace product table (padded columns, product emojis, HTML-safe escaping) and sends it to that region's Telegram chat
   - **Company-wide summary** — ranks all regions by total value, aggregates top-selling products across the whole business, and sends a consolidated overview to a management Telegram chat
5. **Deliver** — Both message types are sent via the Telegram Bot API using HTML parse mode

## Stack

- **n8n** — workflow orchestration, scheduled trigger
- **PostgreSQL** — order/region/product data, aggregation via `json_agg`
- **JavaScript (Code nodes)** — report formatting, ranking, monospace table construction
- **Telegram Bot API** — automated message delivery to multiple chats

## Notable technical details

- **Idempotent test-data seeding** — the reseed query checks whether today's date already has orders before inserting, so the workflow can safely run multiple times a day (or be re-triggered for a demo) without duplicating data. Fake orders are generated deterministically using `hashtext()` on a row index, rather than true randomness, so runs are reproducible.
- **SQL-side JSON aggregation** — rather than shaping the data in JavaScript, the Postgres query itself nests each region's product breakdown into a JSON array with `json_agg`, keeping the downstream Code nodes focused purely on formatting/presentation.
- **Manual monospace table rendering** — Telegram's HTML parse mode doesn't support real tables, so columns are aligned by hand with `padStart`/`padEnd` inside a `<pre>` block, with all dynamic content HTML-escaped to avoid breaking the markup.
- **Two independent consumers of one query** — the same aggregated Postgres output branches into both the per-region formatter and the company-wide summary, avoiding a duplicate database round-trip.

## Notes on this version

This is a **testing/demo build**: all order, customer, and region data referenced here is synthetic, generated by the seed query itself — no real business or customer data is included in this repository. The management Telegram chat ID has been redacted (`[MANAGEMENT_TELEGRAM_CHAT_ID]`); replace it with your own chat ID, and reconnect your own Postgres and Telegram credentials in n8n before running.
